# Connecting Entities

`make web WORLD=<id>` shows which parts of a world depend on mythic or renowned entities for every path between them. Use this procedure to add specific places, objects, work, resources, dangers, or disputes between the separated parts.

If the prose already describes a connection, add the missing edge instead of inventing another entity.

## 1. Measure

Run `make web WORLD=<id>`. Read the second result, which excludes both mythic and renowned entities.

Work from the entries listed alone and from groups that have no path to one another.

## 2. Choose a pair

Choose two entries from different groups. Both should have recognized, marginal, or forgotten prominence. Prefer entries from different regions, civilizations, or kinds.

Read both entries and their existing relationships. If their prose already establishes a connection, add its edge and choose another pair.

## 3. Name three candidates before choosing one

Ask what a person could encounter because both things exist. List three answers before choosing one. Useful answers include:

- a place where the two systems physically meet, and what it is like to be there
- an object both sides need and neither owns
- a trade that exists because the gap exists
- work that exists only because the two sides differ
- something both want and cannot both have
- a danger both face and neither can fix
- a quarrel one has not forgiven the other for
- an intermediary who serves neither party

Write down three before choosing. The first answer is usually the most obvious, not the strongest.

Each answer must be something a reader can picture without learning a rule. Do not propose a document, form, card, register, count, sitting, inspection, protocol, contract, or accord. If an answer requires an explanation of how it is administered, choose another answer.

## 4. Research a less obvious connection

Name the real-world counterpart of each entry: the institution, trade, organism, belief, or practice it most resembles. Research how those two counterparts affect one another. Do not rely on memory, which tends to return the same few answers.

Look for a shared dependency, a way both fail, a useful idea from one field, or a biological fact neither can change. Do not use mere proximity; two things sitting beside one another reveal nothing about either one.

Keep what somebody stands to lose. A dependency shows who is at another's mercy. A shared failure shows what both sides fear and how they act after it happens. A biological fact establishes a limit nobody can negotiate away.

Research on institutions often returns an interval, threshold, certificate, or liability rule because those are the details institutions publish. Discard that machinery. Use the dependency, loss, fear, or physical limit that made the rule necessary.

For example, one settlement controls a spring and another has the only smithy nearby. Irrigation and furnace work need the same labour at the same time of year. That fact could produce an entry about the disputed season, an old grudge, a family with marriages in both settlements, or the person blamed for the last failure. It does not call for an entry about a labour schedule.

This research does not replace the unrelated source of detail required by a world's authoring method. Use both when that method calls for it.

## 5. Keep an answer that is new

If an existing entity is the obvious answer, the pair was already connected. Return to step 2 and choose another pair.

Prefer an answer that could have many examples across the world, then write the one example that matters here. Do not invent a unique institution whose only purpose is to connect distant places.

## 6. Prefer places, things, trades, and grievances

These can connect two parts of the world without giving another role to a famous person. A named intermediary is often the first answer, but repeated intermediaries make every connection run through the same few people.

Write a person only when the connection is personal, such as a debt, family history, or trusted skill. Do not reuse the same person to join another pair.

## 7. Accept a chain

If the two entries need two intermediate entities to form a credible path, write the nearer one now and leave the other for a later pass. Do not make one entity span half the world.

## 8. Set prominence below both entries

An entity between two recognized entries is usually marginal. If either entry is marginal or forgotten, the new entity is usually forgotten. Raise the prominence only when its fame is established independently of this task.

This prevents the new entries from becoming another tier of famous entities. The prominence check then limits their names to nearby or directly connected entries.

## 9. Add the relationships

Add typed relationships from the new entity to both entries. If its prose needs a mythic or renowned entity to explain the connection, return to step 3 and choose something closer to the two entries.

## 10. Write the entry

Follow the world's authoring method. Choose the observer, use the required unrelated source of detail, and add every relationship established by the prose.

## 11. Check the result

Run the world's checks, then run `make web WORLD=<id>` again. Stop when the two groups have a path that does not pass through a mythic or renowned entity.
